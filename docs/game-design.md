# Nova 游戏化设计手册

> 版本：v1.1 | 状态：与 PLAN.md 同步 | 适用范围：前端界面、动效、文案

---

## 1. 核心隐喻

Nova 不是"带皮肤的笔记工具"，而是一座**个人天文台**。

- 每个项目是宇宙中的一颗星
- 写作是给星体注入质量
- 升级为站点是点燃聚变，成为恒星
- 部署是向深空发射信标
- AI 副官是天文台的观测助手
- 设置页是天文台的控制台 / 信标调谐器

所有界面元素都应让人联想到：星图、望远镜控制台、轨道数据、光信号、深空探测。

## 2. 视觉身份

### 2.1 色彩宇宙

Nova 不使用"暗色模式/亮色模式"这种通用命名，而是有自己的色彩宇宙：

| 名称 | 角色 | 暗色参考 | 亮色参考 | 用途 |
|---|---|---|---|---|
| **Void / Atmosphere** | 背景主色 | `#0B0B14` | `#FBF3E8` | 星图、主界面背景 |
| **Dust / Cloud** | 面板背景 | `#1E1A2E` | `#FFF8EE` | 浮层、弹窗、面板 |
| **Surface / Horizon** | 二级面板 | `#2E2940` | `#F5E6D3` | 嵌套面板、AI 日志区 |
| **Nebula（星云）** | 主强调色 | `#6B5BFF` | `#7A6AE8` | 交互高亮、AI 副官、链接 |
| **Nova（新星）** | 暖强调色 | `#FF6B6B` | `#E85A4F` | 按钮、部署信标、成功状态 |
| **Starlight（星光）** | 正文/标题 | `#E8E4FF` | `#3A2A20` | 主要文字 |
| **Star-dim（暗星）** | 次要文字 | `#B0AAD0` | `#7A5A4A` | 辅助说明、次要文本 |
| **Star-faint（微星）** | 最弱文字 | `#7A7399` | `#A88870` | 禁用态、极辅助文字 |
| **Orbit（轨道）** | 分割线/边框 | `rgba(232, 228, 255, 0.08)` | `rgba(101, 70, 50, 0.10)` | 卡片边框、分隔线 |

**暗色模式对比度保障**（背景 = Void `#0B0B14`）：

| 文字角色 | 对比度 | 最小字号 |
|---|---|---|
| Starlight | ~15.5:1 (AAA) | 无限制 |
| Star-dim | ~6.2:1 (AA enhanced) | 0.65rem 及以上 |
| Star-faint | ~4.5:1 (AA minimum) | >= 0.75rem；禁止用于 micro 字号 |
| Nova 强调 | ~5.8:1 (AA) | 按钮、链接均可 |
| Nebula | ~3.5:1 (AA large) | 仅图标/大字/装饰；禁做正文色 |

**层级分离设计目标**：
- Void → Dust：亮度差 ΔL >= 6%（面板在普通显示器上可明确区分）
- Dust → Surface：亮度差 ΔL >= 6%（嵌套层级清晰）

> 代码实现在 `src/theme.ts` 的 `T.dark.*` / `T.light.*`；token 文档在 `docs/design-tokens.md` §2。**当前代码尚未更新至上述色值——P1 修复任务。**

### 2.2 字体系统

字体承载 Nova 的个性：

- **显示字体（Display）**：Fraunces（variable font，带 `opsz` 和 `SOFT` 轴）
  - 用于大标题、页面名称、星图标签
  - 略带手写温度的科技感
- **正文字体（Body）**：IBM Plex Sans（中文 fallback：PingFang SC / Hiragino Sans GB）
  - 用于说明、列表、对话内容
- **等宽字体（Mono）**：JetBrains Mono
  - 用于端口、ID、模型名、Base URL、时间戳

字号层级：

| 层级 | 用途 | 大小 | 响应式(narrow) |
|---|---|---|---|
| 页面标题 | hero 大标题 | 2.2rem | → 1.6rem |
| 区域标题 | "模型供应商""应用设置" | overline / 0.75rem | 不变 |
| 正文 | 说明文案 | 0.95rem | 不变 |
| 数据 | 端口、ID、模型名 | 0.8rem / mono | 不变 |
| 微标 | source chip、状态点 | 0.65rem | → 0.7rem |

完整 token 定义见 `docs/design-tokens.md` §3。

### 2.3 标志性元素

Nova 的"签名元素"是：**星体状态环 + 信标脉冲**。

- 每个项目/供应商/关键对象都用一个"状态环"表示活跃度
- 环的亮度、颜色、脉冲频率编码状态（空闲、活跃、完成、警告）
- 完成重要动作时，从触发点向外发射一次短暂的光束/脉冲

这个元素要反复出现在：
- Dashboard 的项目星体
- Settings 的供应商列表
- AI 副官面板的状态指示
- 按钮的点击反馈

## 3. 游戏化闭环

### 3.1 行动 → 反馈 → 成长 → 奖励

| 产品动作 | 游戏化表达 | 即时反馈 | 成长 |
|---|---|---|---|
| 创建项目 | 种下一颗星 | 粒子爆裂（24 颗，从星图中心发出） | 星数 +1 |
| 创建纯笔记 | 星胚诞生 | 微弱星光脉冲 | 内容质量积累 |
| 保存内容 | 星等提升 | 轻微脉冲（12 颗粒子，不打断书写） | 字数/内容数累计 |
| 升级为站点 | 点亮为恒星 | 主爆裂 40 颗 + 次爆裂 24 颗（Nebula 紫） | 项目形态改变 |
| 部署站点 | 发射信标 | **定向光束**从星体向上发射（0.8s）+ 冲击波 | 阶段升至**星港** |
| 删除项目 | 星体退场 | 白色闪光 + 冲击波扩散 | 星数 -1 |
| 配置供应商 | 调谐信标 | 连接成功时 OrbitRing 稳定亮起 | AI 能力可用 |
| 连续 7 天 streak | 轨道稳定 | OrbitRing 金色闪烁 + toast "轨道已稳定" | 天文台里程碑 +1 |
| 连续 30 天 streak | 引力锁定 | 全屏流星雨 1.5s + AI 副官祝贺消息 | 天文台里程碑 +1 |
| 每 5 个项目 | 星系扩展 | 流星雨彩蛋（12 颗流星横穿屏幕） | 天文台里程碑 +1 |

> 事件类型定义在 `src/lib/events.ts` 的 `NovaEvent` union。**当前代码缺少 `deploy` 和 `streak` 事件类型——待补充。**

### 3.2 星体阶段

| 阶段 | 条件 | 视觉表现 |
|---|---|---|
| 星尘 | 刚创建，无内容 | 暗淡星点，几乎不可见（r=4, fill=starFaint） |
| 星胚 | 1-2 篇笔记/内容 | 小星，微弱白光（r=6, fill=starDim） |
| 新星 | 3+ 篇内容或 1000+ 字 | 明亮星，开始有微光晕（r=9, fill=Nebula） |
| 恒星 | 已升级为站点（kind=site） | 明显光环，暖色 Nova 红（r=12, fill=Nova） |
| 星港 | 已部署（deploy_history 有记录） | 信标脉冲，周期性光束（r=15, fill=Corona） |

> **重要修正**：星港阶段由 `deploy_history` 表中存在部署记录触发，**不再由字数 >= 1000 触发**。当前代码（`Dashboard.tsx` StarMap 映射）仍使用字数判定，需同步修复。

### 3.3 天文台统计

底部常驻一条轻量"天文台"读数：

| 指标 | 说明 | 庆祝阈值 |
|---|---|---|
| 星数 | 项目总数 | 每 5 个触发流星雨 |
| 字数 | 所有 note/site 内容累计字数 | — |
| 连续天数 | 连续写作/更新天数 | 7 天 → "轨道稳定"；30 天 → "引力锁定" |
| 里程碑 | OrbitRing 指示器 | 脉冲表示有新达成 |

## 4. 关键界面设计方向

### 4.1 设置页：天文台控制台

设置页应让人感觉在调谐深空通信设备，而不是填写表单。

#### 端口设置
- 两个端口输入框并排，像"坐标输入器"
- 数字变化时，输入框右侧出现极短的"同步脉冲"光点
- 自动保存用文案"已同步至星图"替代"保存成功"

#### 供应商列表
- 每条供应商不是表格行，而是"轨道条目"
- 左侧有一个状态环：
  - 空环 = 未配置
  - 稳定微光 = 已配置但未被选中
  - 脉冲光环 = 当前 AI 副官正在使用
- 右侧显示模型名用 mono 字体，像频率读数
- "删除"按钮做成"断开连接"图标（unlink / satellite-off）

#### 添加供应商弹窗
- 标题从"添加"改为"调谐信标"
- 供应商选择器像"频段选择器"
- API Key 输入框标签改为"接入密钥"
- "获取模型列表"按钮改为"扫描频段"
- 模型列表以"信号强度网格"呈现，选中的模型高亮为"锁定"

### 4.2 AI 副官面板：舰桥通讯台

- 整体像从底部升起的全息投影台
- 当前供应商显示为"通讯链路：{label}"
- 输入框像命令行终端，`>` 提示符
- 发送按钮做成"发射"图标，hover 时有轻微充能动画（scale 脉冲 + opacity 渐增，模拟能量聚集→释放）
- 回复区域像星图投影，文字淡入

### 4.3 Dashboard：星图

- 项目以星体散布在深色背景上
- 不使用传统卡片网格
- 星体大小/亮度/光环反映项目阶段
- 鼠标悬停显示轨道信息卡片
- 支持缩放、拖拽

### 4.4 编辑器交互模型（Bear 风格）

Nova 的编辑器追求 Bear App 的流畅感：**打开即写、写完即存、最少干扰**。

#### 即时创建
- 点击 `+` 或 `Cmd+N` → 立即在文件系统创建一条空记录，无对话框、无表单
- 新条目出现在侧栏列表顶部，编辑器自动聚焦到内容区
- 项目 kind=note 时新建即 untitled note；kind=site 时新建即 untitled post
- 创建耗时 < 100ms（无网络请求阻塞）

#### 内联标题
- 编辑器**无独立标题字段**
- 第一行文本自动提取为 title：
  - 若第一行是 `# Title` → 去 `#` 取为 title
  - 若第一行是普通文本 → 截断 60 字符取为 title
  - 标题在侧栏列表实时同步更新
- 空内容时 title 显示为"未命名"

#### 内联标签
- 用户在正文任意位置写 `#tag`
- 保存时自动解析 `#tag` 并写入 frontmatter `tags: []`
- 编辑器内 `#tag` 渲染为高亮 chip 样式（可点击跳转筛选）
- 不再有独立的 "标签" 输入框

#### 自动保存
- **800ms debounce** 自动保存（真正 persist 到文件系统）
- 替代当前的 localStorage 草稿 + 手动保存按钮模式
- 底部状态行显示最近一次同步时间戳："已同步 12:34:56"
- 需后端支持：Rust 新增 incremental save 命令

#### 手动同步
- 保留一个 **"同步"** 按钮（原"保存"）
- 作用：force-flush 当前编辑状态 + 触发 "已同步至星图" 脉冲反馈
- 不再是日常操作，仅用于用户想确认数据已落盘的场景

#### 预览
- **默认隐藏**（当前默认 ON 占 50% 是痛点）
- Toggle 键或快捷键展开（侧滑出现，50% 宽度）
- note 项目：Markdown 渲染预览
- site 项目：iframe Astro dev server 预览

#### 类型选择器
- 创建时**不展示** blog/vlog/gallery 选择器
- 类型通过 frontmatter `type:` 字段控制（高级用户手动编辑）
- 或在侧栏项目属性面板中设置（P2）

#### 新条目入场
- 创建瞬间不播放全屏动效（保持流畅）
- 侧栏列表新条目用 fade-in 0.25s 入场

#### 状态行
- 编辑器底部固定一行：
  - 左：`已同步 {timestamp}` 或 `正在同步…`
  - 右：OrbitRing(阶段色) + 星尘质量 `{wordCount} 字` + 阶段标签 chip

## 5. 动效边界

游戏化不能牺牲效率。

| 场景 | 规则 |
|---|---|
| 首次启动 | 最多 1.2 秒开场仪式；日常启动不重复 |
| 创建/升级/部署 | 可以有短促仪式感动效 |
| 保存/输入/滚动 | 禁止重动效，优先流畅 |
| 主题切换 | 接近瞬时 |
| 星图背景 | 低帧率、低密度、tab 隐藏时暂停 |
| 成就/彩蛋 | 只在关键里程碑触发，不常驻 |
| 窄屏 (< 768px) | transform 动效时长减半；milestone 彩蛋改为 toast（不播全屏效果） |
| reduced-motion + 窄屏 | 全部 instant（0s）；仅保留 opacity 过渡 0.15s |

### 性能红线
- 不使用持续 Canvas 动画干扰打字（编辑器页无 Starfield）
- 不使用 `blur()` BackdropFilter 做大面积背景
- 所有动画必须支持 `prefers-reduced-motion`
- 星图背景在页面不可见时暂停
- 编辑器创建新条目必须 < 100ms 完成（无对话框、无网络阻塞）

## 6. 文案语气

Nova 的文案是"观测助手的语气"：专业、简洁、略带诗意，不卖萌、不技术化。

- 不说"API Key"，说"接入密钥"
- 不说"保存成功"，说"已同步至星图"
- 不说"删除"，说"断开连接"或"让星体退场"
- 不说"加载中"，说"正在扫描…"
- 空状态要给出下一步方向，而不是只说"暂无数据"

## 8. 禁忌清单

为了让 Nova 不落入"AI 生成的默认暗色皮肤"陷阱：

- ❌ 不要使用大面积渐变背景作为页面主背景
- ❌ 不要使用霓虹色描边按钮
- ❌ 不要给每个卡片都加发光阴影
- ❌ 不要使用通用占位图标（如齿轮、用户头像）直接作为视觉焦点
- ❌ 不要把"星系主题"做成只在背景加几个圆点
- ❌ 不要在编辑器里放干扰写作的持续动效
- ❌ 不要在创建新内容时弹对话框阻断流程
- ✅ 应该把主题渗透到控件形态、文案、动效、空状态里
- ✅ 应该让编辑器像 Bear 一样安静——打开即写、写完即存

## 9. 响应式设计约束

Nova 是 Tauri 桌面应用，但窗口可任意缩放。必须支持 768px 最小宽度优雅降级。

### 9.1 断点定义

| 名称 | 条件 | 描述 |
|---|---|---|
| narrow | 窗口宽度 < 768px | 分屏半幅、极端小窗口 |
| medium | 768px – 1024px | 笔记本全屏、分屏 60% |
| wide | > 1024px | 外接显示器、全屏 |

断点 token 见 `docs/design-tokens.md` §4.2。

### 9.2 各页面/组件响应行为

| 页面/组件 | narrow (< 768px) | medium (768–1024px) | wide (> 1024px) |
|---|---|---|---|
| Dashboard 星图 | 列表视图替代 SVG 星图 | StarMap clamp(300px, 50vh, 600px) | StarMap 完整交互 |
| 侧栏 | 抽屉模式 / icon rail 40px | 200px permanent（紧凑标签） | 260px permanent |
| 编辑器预览 | tab/overlay 切换 | 默认隐藏 | 可切换 50% 宽度 |
| Observatory | 单行折叠："5星 · 1.2k字 · 3天" | 3 指标紧凑（隐藏 milestone） | 完整 4 指标 + milestone |
| AI 副官面板 | 全宽 overlay | 底部固定（960px max-width） | 底部固定（960px max-width） |
| 创建项目 dialog | **取消 dialog**——Bear 风格即时创建 | 同左 | 同左 |

### 9.3 设计原则

- **桌面优先**：wide 是设计基准；medium/narrow 是优雅降级
- **不丢信息**：narrow 下信息全在，只是交互方式不同（折叠/tab/overlay）
- **内容为王**：窗口越小，编辑器区域占比越大；chrome 越少
- **触摸兼容**：虽然是桌面应用，narrow 模式下点击目标 >= 44px（未来触屏笔记本）

### 9.4 实现优先级

- **P1**：medium 断点（最常见的分屏/小窗口场景）— 预览自动隐藏、侧栏紧凑
- **P2**：narrow 断点（极端小窗）— 侧栏折叠、StarMap 切列表、Observatory 折叠
