# Nova 游戏化设计手册

> 版本：v1.0 | 状态：与 PLAN.md 同步 | 适用范围：前端界面、动效、文案

---

## 1. 核心隐喻

Nova 不是“带皮肤的笔记工具”，而是一座**个人天文台**。

- 每个项目是宇宙中的一颗星
- 写作是给星体注入质量
- 升级为站点是点燃聚变，成为恒星
- 部署是向深空发射信标
- AI 副官是天文台的观测助手
- 设置页是天文台的控制台 / 信标调谐器

所有界面元素都应让人联想到：星图、望远镜控制台、轨道数据、光信号、深空探测。

## 2. 视觉身份

### 2.1 色彩宇宙

Nova 不使用“暗色模式/亮色模式”这种通用命名，而是有自己的色彩宇宙：

| 名称 | 角色 | 参考色值 | 用途 |
|---|---|---|---|
| **Void（深空）** | 背景主色 | `#0a0b10` | 星图、主界面背景 |
| **Nebula（星云）** | 主强调色 | `#6d5dfc` / `#a855f7` | 交互高亮、AI 副官、按钮 |
| **Corona（日冕）** | 暖强调色 | `#f59e0b` / `#fbbf24` | 恒星、部署信标、成功状态 |
| **Starlight（星光）** | 正文/标题 | `#e8e9ec` | 主要文字 |
| **Star-dim（暗星）** | 次要文字 | `#8b8f98` | 辅助说明、禁用态 |
| **Orbit（轨道）** | 分割线/边框 | `rgba(148, 163, 184, 0.15)` | 卡片边框、分隔线 |
| **Dust（星尘）** | 浮层背景 | `rgba(15, 23, 42, 0.85)` | 弹窗、面板 |
| **Atmosphere（大气）** | 亮色主题背景 | `#f6f5f2` | 浅色模式主背景 |

> 注：当前代码里的 `theme.ts` 变量命名（`t.star`、`t.nova`、`t.border` 等）可以继续使用，但应在文档和注释中映射到上述概念名，并在未来逐步替换为更贴切的命名。

### 2.2 字体系统

字体承载 Nova 的个性。建议：

- **显示字体（Display）**：用于大标题、页面名称、星图标签
  - 推荐：`Space Grotesk` 或 `Exo 2` —— 略带科技感的几何无衬线，有“航天器仪表”气质
  - 当前 `FONT.display` 需要切换到这一类字体
- **正文字体（Body）**：用于说明、列表、对话内容
  - 推荐：`Inter` 或系统默认无衬线 —— 保证可读性
- **等宽字体（Mono）**：用于端口、ID、模型名、Base URL
  - 推荐：`JetBrains Mono` 或 `SF Mono` —— 控制台数据感

字号层级：

| 层级 | 用途 | 大小 |
|---|---|---|
| 页面标题 | “让 Nova 认识你”这类大标题 | 2.2rem / 粗体 400 |
| 区域标题 | “模型供应商”“应用设置” | overline / 0.75rem |
| 正文 | 说明文案 | 0.875rem |
| 数据 | 端口、ID、模型名 | 0.8rem / mono |
| 微标 | source chip、状态点 | 0.65rem |

### 2.3 标志性元素

Nova 的“签名元素”是：**星体状态环 + 信标脉冲**。

- 每个项目/供应商/关键对象都用一个“状态环”表示活跃度
- 环的亮度、颜色、脉冲频率编码状态（空闲、活跃、完成、警告）
- 完成重要动作时，从触发点向外发射一次短暂的光束/脉冲

这个元素要反复出现在：
- Dashboard 的项目星体
- Settings 的供应商列表
- AI 副官面板的状态指示
- 按钮的点击反馈

## 3. 游戏化闭环

### 3.1 行动 → 反馈 → 成长 → 奖励

| 产品动作 | 游戏化表达 | 即时反馈 | 成长 |
|---|---|---|---|
| 创建项目 | 种下一颗星 | 星点从暗到亮 | 星数 +1 |
| 创建纯笔记 | 星胚诞生 | 微弱星光 | 内容质量积累 |
| 保存内容 | 星等提升 | 轻微脉冲 | 字数/内容数累计 |
| 升级为站点 | 点亮为恒星 | 光环扩散 | 项目形态改变 |
| 部署站点 | 发射信标 | 星体向外发射光束 | 可访问地址生成 |
| 删除项目 | 星体退场 | 星点塌缩/消散 | 星数 -1 |
| 配置供应商 | 调谐信标 | 连接成功时光环稳定亮起 | AI 能力可用 |

### 3.2 星体阶段

| 阶段 | 条件 | 视觉表现 |
|---|---|---|
| 星尘 | 刚创建，无内容 | 暗淡星点，几乎不可见 |
| 星胚 | 1-2 篇笔记/内容 | 小星，微弱白光 |
| 新星 | 3+ 篇内容或 1000+ 字 | 明亮星，开始有微光晕 |
| 恒星 | 已升级为站点 | 明显光环，暖色（Corona） |
| 星港 | 已部署 | 信标脉冲，周期性光束 |

### 3.3 天文台统计

底部常驻一条轻量“天文台”读数：

| 指标 | 说明 |
|---|---|
| 星数 | 项目总数 |
| 字数 | 所有 note/site 内容累计字数 |
| 连续天数 | 连续写作/更新天数 |
| 里程碑 | 每 5 个项目或首次部署触发轻量奖励 |

## 4. 关键界面设计方向

### 4.1 设置页：天文台控制台

设置页应让人感觉在调谐深空通信设备，而不是填写表单。

#### 端口设置
- 两个端口输入框并排，像“坐标输入器”
- 数字变化时，输入框右侧出现极短的“同步脉冲”光点
- 自动保存用文案“已同步至星图”替代“保存成功”

#### 供应商列表
- 每条供应商不是表格行，而是“轨道条目”
- 左侧有一个状态环：
  - 空环 = 未配置
  - 稳定微光 = 已配置但未被选中
  - 脉冲光环 = 当前 AI 副官正在使用
- 右侧显示模型名用 mono 字体，像频率读数
- “删除”按钮做成“断开连接”图标（unlink / satellite-off）

#### 添加供应商弹窗
- 标题从“添加”改为“调谐信标”
- 供应商选择器像“频段选择器”
- API Key 输入框标签改为“接入密钥”
- “获取模型列表”按钮改为“扫描频段”
- 模型列表以“信号强度网格”呈现，选中的模型高亮为“锁定”

### 4.2 AI 副官面板：舰桥通讯台

- 整体像从底部升起的全息投影台
- 当前供应商显示为“通讯链路：{label}”
- 输入框像命令行终端，`>` 提示符
- 发送按钮做成“发射”图标，hover 时有轻微充能动画
- 回复区域像星图投影，文字淡入

### 4.3 Dashboard：星图

- 项目以星体散布在深色背景上
- 不使用传统卡片网格
- 星体大小/亮度/光环反映项目阶段
- 鼠标悬停显示轨道信息卡片
- 支持缩放、拖拽（P2）

## 5. 动效边界

游戏化不能牺牲效率。

| 场景 | 规则 |
|---|---|
| 首次启动 | 最多 1.2 秒开场仪式；日常启动不重复 |
| 创建/升级/部署 | 可以有短促仪式感动效 |
| 保存/输入/滚动 | 禁止重动效，优先流畅 |
| 主题切换 | 接近瞬时 |
| 星图背景 | 低帧率、低密度、tab 隐藏时暂停 |
| 成就/彩蛋 | 只在关键里程碑触发，不常驻 |

### 性能红线
- 不使用持续 Canvas 动画干扰打字
- 不使用 `blur()` BackdropFilter 做大面积背景
- 所有动画必须支持 `prefers-reduced-motion`
- 星图背景在页面不可见时暂停

## 6. 文案语气

Nova 的文案是“观测助手的语气”：专业、简洁、略带诗意，不卖萌、不技术化。

- 不说“API Key”，说“接入密钥”
- 不说“保存成功”，说“已同步至星图”
- 不说“删除”，说“断开连接”或“让星体退场”
- 不说“加载中”，说“正在扫描…”
- 空状态要给出下一步方向，而不是只说“暂无数据”

## 8. 禁忌清单

为了让 Nova 不落入“AI 生成的默认暗色皮肤”陷阱：

- ❌ 不要使用大面积渐变背景作为页面主背景
- ❌ 不要使用霓虹色描边按钮
- ❌ 不要给每个卡片都加发光阴影
- ❌ 不要使用通用占位图标（如齿轮、用户头像）直接作为视觉焦点
- ❌ 不要把“星系主题”做成只在背景加几个圆点
- ✅ 应该把主题渗透到控件形态、文案、动效、空状态里
